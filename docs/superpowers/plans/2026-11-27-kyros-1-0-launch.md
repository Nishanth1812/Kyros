# Kyros 1.0.0 Launch Plan

> **For agentic workers:** Use `superpowers:executing-plans` to complete this plan task by task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Release the Kyros 1.0.0 candidate with the approved product-readiness improvements as a signed Android APK.

**Architecture:** Keep the release-only version and documentation update on `dev`. The
product-readiness code slices (savings rate, backup version, Settings/navigation, screen
hierarchy/accessibility, chart clarity) are implemented; runtime verification, signed
build/release checks, and wiki alignment remain pending. The existing push-to-`main`
workflow remains responsible for tests, signing, artifact verification, tagging, and
GitHub Release publication. No schema change and no account or network feature are included.

**Tech Stack:** React Native 0.88.1, TypeScript 6, SQLite schema v4, Android Gradle, Bun, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-11-27-kyros-1-0-launch-design.md`
**Product-readiness plan:** `docs/superpowers/plans/2026-11-27-kyros-1-0-product-readiness.md`

## Global Constraints

- Android remains the supported platform with minimum API 24.
- Financial data remains in local SQLite at schema v4; money remains integer paise.
- Use the existing release keystore for upgrades.
- Latest published release is `v0.6.2`, versionCode 12; 1.0.0 must use versionCode 13.
- Accounts, cloud sync, backend services, and network transport remain outside 1.0.
- Performance measurement/optimization and device or signed-APK checks are not claimed
  complete without evidence; no performance result is reported here.

## Review Focus

- **Version mismatch:** `package.json`, both package-lock root versions, and Gradle
  `versionName` must say `1.0.0`; verify them together.
- **Version code regression:** CI must derive versionCode 13 from the `v0.6.2` tag's
  versionCode 12; check the annotated tag and release workflow result.
- **Signing identity:** an upgrade must use the same certificate as 0.6.2; verify the
  published APK certificate fingerprint against the existing release key.
- **Data continuity:** the schema remains v4; install 1.0 over representative 0.6.2 data
  and confirm all saved records, settings, and backups remain available, and that new
  backups report 1.0.0.
- **Shipped-scope drift:** user documentation must describe the implemented savings-rate,
  backup-version, Settings/theme, navigation, accessibility, and chart behavior without
  claiming accounts, cloud sync, network features, or measured performance.
- **Release guidance drift:** user documentation and the published wiki must describe the
  actual 1.0 behavior and local-only data handling before release reaches `main`.
