# Kyros 1.0.0 Stable Launch Plan

> **For agentic workers:** Use `superpowers:executing-plans` to complete this plan task by task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Release the current Kyros feature set as a signed 1.0.0 Android APK.

**Architecture:** Make a release-only version and documentation update on `dev`. The existing push-to-`main` workflow remains responsible for tests, signing, artifact verification, tagging, and GitHub Release publication. No app behavior or schema changes are included.

**Tech Stack:** React Native 0.88, TypeScript 6, SQLite schema v4, Android Gradle, Bun, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-11-27-kyros-1-0-launch-design.md`

## Global Constraints

- Android remains the supported platform with minimum API 24.
- Financial data remains in local SQLite; money remains integer paise.
- Use the existing release keystore for upgrades.
- Latest published release is `v0.6.2`, versionCode 12; 1.0.0 must use versionCode 13.
- Product improvements suggested for later work and connected services remain outside 1.0.

## Review Focus

- **Version mismatch:** `package.json`, both package-lock root versions, and Gradle `versionName` must say `1.0.0`; verify them together.
- **Version code regression:** CI must derive versionCode 13 from the `v0.6.2` tag's versionCode 12; check the annotated tag and release workflow result.
- **Signing identity:** an upgrade must use the same certificate as 0.6.2; verify the published APK certificate fingerprint against the existing release key.
- **Data continuity:** the schema remains v4; install 1.0 over representative 0.6.2 data and confirm all saved records and settings remain available.
- **Release guidance drift:** user documentation and the published wiki must describe the actual 1.0 behavior and local-only data handling.
